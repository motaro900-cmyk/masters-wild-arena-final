**Дата актуализации**: 2026-08-29

## 1. Архитектура хранения и отказоустойчивости

- **Среда**: Автономный российский VPS (Node.js).
- **Хранилище**: Локальные JSON-документы в каталоге `server/data/пользователи/` и `server/data/пользователи_dev/`.
- **Механизм защиты записи**:
  1. Данные сериализуются и записываются во временный файл `[docId].json.tmp.[timestamp]_[random]`.
  2. Существующий валидный файл копируется в резервный файл `[docId].json.bak`.
  3. Выполняется атомарная операция переименования `fs.rename` из `.tmp` в целевой `[docId].json`.
- **Защита от конкурентности**: Попользовательский асинхронный мьютекс (`userLocks` в `transactionManager.js`), гарантирующий строго последовательное применение операций одного игрока.

## 2. Сценарии аварийных ситуаций и их устранение

### Сценарий A: Повреждение отдельного JSON-файла игрока
**Симптомы**: `SyntaxError: Unexpected token in JSON at position ...` при чтении профиля.  
**Автоматическое поведение**: Модуль `localStore.js` при ошибке парсинга автоматически пытается прочитать файл `[docId].json.bak`, восстанавливает его в основной `[docId].json` и логирует предупреждение в журнал.  
**Ручное восстановление (при необходимости)**:
```bash
# Восстановление из локального .bak
cp server/data/пользователи/VK-123456.json.bak server/data/пользователи/VK-123456.json
```

### Сценарий B: Оба файла (main и .bak) повреждены
**Симптомы**: Файлы пусты (0 байт) или повреждены на уровне файловой системы.  
**Действие**:
1. Сервер **НЕ ПРИДУМЫВАЕТ** фейковые данные с валютой.
2. Профиль инициализируется со стартовым безопасным балансом (500 gold, 10 crystals, 100 energy, 1 lvl) и версией ревизии 1.
3. Логируется инцидент безопасности для проверки истории оплат `server/data/покупки/`.

### Сценарий C: Неожиданный сбой питания или перезапуск VPS
**Симптомы**: Процесс Node.js был аварийно завершён (SIGKILL / Kernel Panic).  
**Действие**:
1. После перезапуска PM2 / `node server/vps-server.js` поднимает сервер за < 1 секунды.
2. Таблица идемпотентности `_processedOps` хранится непосредственно внутри JSON каждого пользователя, поэтому повторные запросы клиентов после восстановления связи корректно распознаются как дубликаты и не вызывают двойных начислений.

## 3. Регламент полного резервного копирования и отката (Backup & Rollback)

### Создание снимка базы данных (Ежедневно в 04:00 МСК):
```bash
# Создание архива базы данных
tar -czf /var/backups/motw_profiles_$(date +%Y%m%d_%H%M%S).tar.gz -C /var/www/masters-of-the-wild/server data/
```

### Восстановление из архива:
```bash
# 1. Остановка сервера
pm2 stop motw-server

# 2. Восстановление каталога data/
tar -xzf /var/backups/motw_profiles_YYYYMMDD_HHMMSS.tar.gz -C /var/www/masters-of-the-wild/server/

# 3. Запуск сервера
pm2 start motw-server

# 4. Проверка работоспособности
curl http://localhost:3000/api/health
```

### Откат версии приложения (Deployment Rollback):
```bash
# В случае обнаружения критического бага в новой сборке фронтенда:
git checkout tags/v1.2.0-rc1
npm run build
pm2 restart motw-server
```
