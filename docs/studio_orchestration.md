# 🧠 Спецификация оркестрации AI-студии (AI Studio Orchestration Specification)

Этот документ описывает протоколы взаимодействия, формат хранения памяти и матрицу разрешения конфликтов между специализированными игровыми AI-агентами. Все агенты обязаны следовать этим стандартам при общении друг с другом.

---

## 1. Стандарт Message Bus (JSON-диалоги)

Каждое сообщение между агентами передается в виде строго валидируемого JSON-объекта. Это гарантирует структурированность диалогов и машиночитаемость истории принятия решений.

### Общая схема сообщения (Base Schema)
```json
{
  "from": "идентификатор_отправителя",
  "to": "идентификатор_получателя",
  "type": "request | report | warning | recommendation",
  "task_id": "уникальный_id_задачи",
  "payload": {},
  "confidence": 0.0
}
```

### Типы сообщений и их Payload

#### 1. `request` (Запрос действия / делегирование)
Отправляется оркестратором (`game_director_agent`) к исполнителю или между агентами при запросе обратной связи.
```json
{
  "from": "game_director_agent",
  "to": "economy_agent",
  "type": "request",
  "task_id": "task_gold_rush_event",
  "payload": {
    "instruction": "Рассчитай суточный лимит золота для ивента 'Золотая Лихорадка' с учетом удержания игроков.",
    "context": {
      "duration_days": 7,
      "target_retention_increase": 0.05
    }
  },
  "confidence": 1.0
}
```

#### 2. `report` (Финальный отчет исполнителя)
Ответ исполнителя на запрос с выводами и результатами работы.
```json
{
  "from": "economy_agent",
  "to": "game_director_agent",
  "type": "report",
  "task_id": "task_gold_rush_event",
  "payload": {
    "summary": "Экономика ивента сбалансирована. Лимит наград установлен в 2500 золота/сутки.",
    "details": {
      "daily_limit": 2500,
      "max_total_reward": 17500,
      "sink_mechanic": "Ввод временного сундука за 3000 золота"
    },
    "risks": [
      "При быстром прохождении возможен избыток золота у 5% хардкорных игроков"
    ],
    "metrics_impact": {
      "inflation_forecast": "+1.2%",
      "retention_d7_forecast": "+2.1%"
    }
  },
  "confidence": 0.92
}
```

#### 3. `warning` (Предупреждение / Блокировка / Veto)
Используется преимущественно `qa_agent` или `economy_agent` для блокировки опасных изменений.
```json
{
  "from": "qa_agent",
  "to": "game_director_agent",
  "type": "warning",
  "task_id": "task_gold_rush_event",
  "payload": {
    "summary": "Обнаружена критическая уязвимость дюпа наград в механике повторного входа.",
    "details": {
      "exploit_type": "double_claim_on_latency",
      "severity": "CRITICAL"
    },
    "risks": [
      "Полное разрушение баланса золота за 24 часа"
    ],
    "proposed_fix": "Добавить серверную валидацию времени транзакции в verify-sign.js"
  },
  "confidence": 1.0
}
```

#### 4. `recommendation` (Дизайнерские правки / Предложения)
Рекомендация по улучшению без жесткой блокировки.
```json
{
  "from": "ux_agent",
  "to": "game_director_agent",
  "type": "recommendation",
  "task_id": "task_gold_rush_event",
  "payload": {
    "summary": "Предлагаю заменить полноэкранный попап на лаконичную плашку уведомления.",
    "details": {
      "element": "GoldRewardPopup",
      "alternative": "Toast Notification"
    },
    "risks": [],
    "metrics_impact": {
      "onboarding_drop_rate": "-0.5%"
    }
  },
  "confidence": 0.85
}
```

## 2. Стандарт системы памяти (Memory System)

Память студии хранится в локальном файле `docs/reports/studio_memory.json` (игнорируется Git). Она содержит текущие экономические константы, историю запусков и паттерны, которые привели к багам или инфляции в прошлом.

### Формат JSON памяти (`studio_memory.json`)
```json
{
  "version": "1.0.0",
  "economy_state": {
    "gold_income_per_day": 1200,
    "inflation_rate": 0.03,
    "average_gold_balance": 5400
  },
  "events_history": [
    {
      "event_id": "winter_2026",
      "result": "high_retention",
      "issues": ["reward_exploit_fixed"]
    }
  ],
  "banned_patterns": [
    "infinite_reward_loop",
    "negative_price_arbitrage",
    "double_claim_on_latency"
  ]
}
```

## 3. Анти-конфликтная матрица (Anti-Conflict Matrix)

Когда мнения агентов расходятся, `game_director_agent` разрешает споры на основе следующей матрицы приоритетов:

| Тип конфликта | Побеждающая сторона | Причина приоритета |
| :--- | :--- | :--- |
| **Критический эксплойт / Дюп** | **`qa_agent` (Veto)** | Любые баги безопасности блокируют релиз до устранения. |
| **Инфляция vs Retention** | **`economy_agent`** | Долгосрочная инфляция разрушает экономику игры сильнее временного спада удержания. |
| **UX дизайн vs Engagement** | **`game_director_agent`** | Директор оценивает общую вовлеченность на основе бизнес-целей. |
| **LiveOps скорость vs Стабильность** | **`economy_agent`** | Запуск новых акций не должен выходить за рамки допустимых эмиссионных лимитов. |
| **Прогрессия vs Сложность** | **`game_designer`** | Геймдизайнер отвечает за долгосрочный интерес к игровому процессу. |

## 4. Слой принятия решений (Decision Lineage)

Вся история принятых директором решений логируется в файл `docs/reports/decision_log.json` (игнорируется Git). Это позволяет сохранять контекст (почему предложение было принято или отклонено), кто из агентов был за/против, и какие альтернативы были рассмотрены.

### Формат записи лога (`decision_log.json`)
```json
{
  "task_id": "идентификатор_задачи",
  "decision": "название_принятого_решения",
  "reasoning_summary": "Краткое обоснование (почему польза превышает риски)",
  "agents_agreed": [
    "список_агентов_которые_одобрили"
  ],
  "agents_conflicted": [
    "список_агентов_выразивших_несогласие"
  ],
  "final_veto": "qa_agent | economy_agent | null",
  "metrics_forecast": {
    "retention_d7": "+1.5%",
    "inflation": "+0.4%"
  }
}
```

## 5. Контроль токенов и оптимизация затрат (Token Control)

Для снижения расхода токенов и предотвращения бесконечных циклов обсуждения вводятся строгие правила вызовов:

1. **Максимум 1 раунд обсуждений (по умолчанию):** Директор опрашивает исполнителей один раз и на основе матрицы приоритетов сразу принимает решение.
2. **Условие второго раунда (Risk > 5%):** Второй раунд итерации запускается только в том случае, если прогнозируемый риск оттока игроков (churn) или инфляции превышает `0.05` (5%).
3. **Ограничение вызовов дорогого QA-агента:** `qa_agent` вызывается только для задач с категорией риска `HIGH` (изменение платежных путей, сохранение игрового прогресса, изменение сигнатур API, прямая запись в Firebase/БД).

---

## 6. Суммаризация отчетов (Agent Summarizer)

Чтобы не перегружать контекстное окно Директора длинными рассуждениями:

1. **Лимит текстового резюме:** Поле `payload.summary` в сообщениях агентов не должно превышать **150 слов**.
2. **Изоляция сырых данных:** Все формулы, таблицы статов, логи работы и списки файлов выносятся строго внутрь объекта `payload.details` и не дублируются в тексте. Агенты обязаны писать лаконично и по существу.

---

## 7. Адаптивный слой рисков (Risk Escalation Layer)

Чтобы оптимизировать затраты и адаптировать глубину анализа, все поступающие задачи классифицируются по 4 уровням риска. Для каждого уровня определен жесткий список участников и лимит раундов (Token Budget Multiplier):

### Матрица градации рисков и пайплайнов

| Уровень риска | Описание / Примеры | Требуемые агенты | Пайплайн и Лимиты | Бюджет (Multiplier) |
| :--- | :--- | :--- | :--- | :--- |
| **LOW** | Изменения текстов интерфейса, описания квестов, визуальные правки, исправления опечаток. | `ux_agent` или `live_ops_agent` | **Минимальный:** 1 агент, строго 1 раунд. Директор принимает решение без созыва студии. | `0.5x` |
| **MEDIUM** | Корректировки базовых статов предметов, баланс урона, простые награды за дейлики. | `game_designer`, `economy_agent` | **Базовый:** 2 агента, 1 раунд. Проверяется инфляция и долгосрочный интерес. | `1.0x` |
| **HIGH** | Запуск акций, временные события, новые цепочки наград, новые предметы/механики. | `live_ops_agent`, `economy_agent`, `ux_agent`, `qa_agent` | **Полный:** 4 агента, 1-2 раунда. Проверяется интерфейс, баланс и уязвимости. | `1.5x` |
| **CRITICAL** | Изменения платежных шлюзов, интеграция VK Pay, сохранение прогресса, баланс хард-валюты, изменение схемы базы данных. | **Все агенты** (Full Studio) | **Максимальный:** Все агенты, 2+ раундов. Veto-контроль от `qa_agent` и `economy_agent`, обязательный синк с `analytics_agent`. | `2.0x` |
