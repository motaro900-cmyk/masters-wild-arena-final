# Правила работы с проектом (Workspace Rules)

## Соответствие требованиям VK Mini Apps (Compliance)

Перед любыми изменениями в коде, связанными с VK API (VK Bridge), платежами, авторизацией, социальными функциями, рекламой или юридическими документами, соблюдайте следующие правила:

1. **Источник истины**: Главным источником нормативных требований проекта является каталог `/compliance/` в корне репозитория.
2. **Анализ перед изменением**: Сначала прочитайте файлы:
   - `/compliance/LAST_VERIFIED.md`
   - `/compliance/VK_MODERATION_CHECKLIST_2026.md`
   - `/compliance/VK_BRIDGE_API_AUDIT_2026.md`
   - `/compliance/VK_PAY_AUDIT_2026.md`
   - `/compliance/VK_PRIVACY_AUDIT_2026.md`
3. **Запрет дрейфа документации**: Не делайте предположений об API ВКонтакте на основе старых данных обучения. Если требования изменились, сначала обновите соответствующий файл в `/compliance/` и зафиксируйте новые правила, а затем вносите изменения в код.
4. **Безопасность платежей**: Запрещено внедрять обходные платежные пути (Bypass/Sandbox) в продакшн-окружение. Любая отладочная эмуляция платежей должна быть скрыта под строгой проверкой `import.meta.env.DEV === true` и `window.location.hostname === 'localhost'`, чтобы компилятор полностью вырезал этот код при сборке.
5. **Внешние ссылки**: Все внешние ссылки должны обрабатываться через `openExternalUrl` с префиксом редиректа `vk.com/away.php?to=`.
