# Архитектура структуры проекта (Architecture Layout Contract)

В данном файле зафиксирован финальный контракт расположения файлов, ресурсов, кода и распределения обязанностей в проекте Masters of the Wild. Все разработчики и автоматизированные скрипты обязаны строго соблюдать эти правила.

---

## 1. Ментальная модель каталогов

Проект разграничен по слоям ответственности:

```
[Исходные ресурсы] (Source Assets)  -->  [Сборщики/Оптимизаторы]  -->  [Конечные ресурсы] (Runtime Assets)
       (assets-src)                       (optimize / atlas)                 (public/assets)
```

```
[Исходный код] (Source Code)        -->  [Компилятор Vite]         -->  [Веб-дистрибутив] (Build Output)
         (src)                              (npm run build)                   (dist)
```

```
[Публичные запросы] (API Requests)  -->  [Прокси-фасад] (Façade)  -->  [Бизнес-логика бэкенда] (Truth)
        (/api/*)                             (/api/*.js)                      (/server/*.js)
```

---

## 2. Классификация каталогов

### 1. Исходные файлы (Source)
* **`/src/`**: Весь клиентский код игры на React/TypeScript.
* **`/assets-src/`**: Сырые, необработанные ресурсы (изображения полного разрешения, несжатые звуки).
* **`/server/`**: Серверная бизнес-логика API-ручек (Source of Truth для бэкенда).
* **`/api/`**: Легковесные фасады/прокси, принимающие внешние запросы от Vercel.
* **`/functions/`**: Cloud Functions для Firebase.
* **`/scripts/`**: Скрипты автоматизации, оптимизации и верификации сборки.
* **`/docs/compliance/`**: Чек-листы соответствия VK Mini Apps (документация).

### 2. Временные и сборочные результаты (Build / Temp Output)
* **`/build/`**: Изолированная, игнорируемая Git папка для промежуточных результатов.
* **`/dist/`**: Конечный собранный бандл игры для продакшена (генерируется Vite).
* **`/temp/`**: Локальный временный кэш генератора атласов.
* **`/archive/`**: Заархивированный устаревший код и лог-файлы (для сохранения истории).

### 3. Ресурсы реального времени (Runtime Assets)
* **`/public/`**: Корень статического хостинга.
* **`/public/assets/`**: Оптимизированные ресурсы (WebP, MP3, атласы), раздаваемые клиенту. **Изменение вручную запрещено.**

---

## 3. Правила и запреты (Enforcement Rules)

### 🚫 Категорически запрещено:
1. **Прямое изменение `/public/assets`**: Сюда попадают только автоматически сжатые и сгенерированные файлы из пайплайна оптимизации.
2. **Использование legacy-директорий**:
   * **`src/assets/`** — устаревший каталог. Ассеты должны лежать в `assets-src/`.
   * **`src/components/`** — устаревший каталог. React UI-компоненты должны находиться в `src/ui/components/`.
   * **`src/engine/stores/`** — устаревший каталог. Глобальный стейт лежит в `src/store/`.
3. **Прямой импорт бэкенда в клиент**: Клиентский код (`src/`) никогда не должен импортировать файлы из `/api/` или `/server/`.
4. **Скрытые кросс-импорты в бэкенде**: Серверный код в `/server/` обязан быть изолированным и не может импортировать модули из `/src/` или `/scripts/`.

### ⚠️ Исключения (Migration Exceptions):
Если импорт из устаревшей директории временно необходим в процессе миграции, используйте следующую конструкцию:
```typescript
// migration-todo: [task-id] remove legacy path
// eslint-disable-next-line no-restricted-imports
import { LegacyAsset } from 'src/assets/...';
```

## 4. Контроль графа зависимостей (Dependency Graph Enforcement)

Соблюдение архитектурных границ автоматически проверяется на двух уровнях:

1. **Линтер ESLint**:
   * Конфигурация [eslint.config.js](file:///c:/Users/Motar/Desktop/Masters%20of%20the%20Wild/eslint.config.js) содержит запрет `no-restricted-imports` на импорт любых путей из `src/assets`, `src/components`, `api` и `server` внутри клиентского кода.
2. **Статический анализатор импортов**:
   * Скрипт [scripts/audit-dependencies.js](file:///c:/Users/Motar/Desktop/Masters%20of%20the%20Wild/scripts/audit-dependencies.js) сканирует все импорты в `/src/` и `/server/` перед каждым запуском CI/CD. Выход с кодом `1` при обнаружении нарушений.
